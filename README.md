## 4. Operating Rules & Workflow Standards
**GitHub Branching Strategy:** No direct commits to main. All work must be done on dedicated feature branches (e.g., feature/jwt-auth, feature/ticket-schema).
**Pull Request (PR) Policy:**
  * Every PR requires at least **one review and approval** from a teammate before merging.
  * PR descriptions must include what was built, testing evidence, and the relevant concept ID.
**Daily Journal Rule:** Every team member submits their individual daily journal before **11:59 PM** without fail.
